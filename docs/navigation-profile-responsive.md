# منوی شناور، پروفایل و واکنش‌گرایی

## رفتار پیاده‌شده

- منوی اصلی در عرض‌های کوچک/متوسط، شناور و خارج از جریان صفحه است. بازشدن ۳۴۰ و بسته‌شدن رو به بالا ۲۳۰ میلی‌ثانیه، فقط با WAAPI انجام می‌شود. کلیک لینک، بیرون پنل، تغییر مسیر، خروج فوکوس و Escape آن را می‌بندد. Escape فوکوس را به کلید برمی‌گرداند. حرکت جاری در کلیک‌های سریع از وضعیت فعلی ادامه/معکوس می‌شود.
- این رابط یک disclosure غیرمودال است، نه `role=menu`: لینک‌ها با Tab پیمایش می‌شوند. هنگام بسته‌شدن، `inert` از فعال‌شدن لینک‌های در حال محو شدن جلوگیری می‌کند. با reduced motion حرکت و مقیاس حذف می‌شود.
- ورود یک دکمه با نماد کلید است؛ در باریک‌ترین عرض‌ها فقط نماد و نام دسترس‌پذیر باقی می‌ماند. بعد از ورود، دایرهٔ تصویر جای آن را می‌گیرد. پنل حساب شامل پروفایل، تحلیلگرها، فروشگاه و خروج است؛ لینک میز مدیریت فقط برای مالک نمایش داده می‌شود. هماهنگی منوها با انتخاب‌گر تم نیز انجام شده است.
- پنل پروفایل نسبت به هدر لنگر می‌گیرد، نه لبهٔ خود آواتار؛ بنابراین در موبایل از صفحه بیرون نمی‌رود. ارتفاع پنل‌ها به viewport محدود و محتوای بلند در همان پنل اسکرول می‌شود؛ پس‌زمینه هل داده یا قفل نمی‌شود.
- اندازهٔ عنوان‌ها و کلاس‌های متن عمومی، فاصله‌های فرم و کارت‌ها، حداقل عرض flex/grid و جست‌وجوی دانشنامه اصلاح شده‌اند. متن‌ها حداقل rem خوانا دارند؛ ریسپانسیو با پنهان‌کردن سراسری overflow شبیه‌سازی نشده است. جدول‌های ذاتاً دوبعدی پنل مدیریت همچنان در محفظهٔ خود اسکرول افقی دارند.

## SVG و ماندگاری

هشت پرترهٔ برداری اصلی و سبک در `public/avatars` وجود دارد؛ به سرویس تصویر خارجی یا اطلاعات شخصی وابسته نیستند. دستور `npm run build:avatars` دارایی‌های ثابت را بازتولید می‌کند. در مرورگر تولید تصادفی دوباره نداریم. پرترهٔ اصلی هادی و مسیر تولید/مصرف آن هیچ تغییری نکرده است.

برای حساب واقعی، انتخاب پیش‌فرض از شناسهٔ داخلی حساب مشتق می‌شود و در اولین ورود/مراجعه در `account_avatars` درج می‌شود. قفل کلید اصلی و مدیریت conflict جلوی تخصیص ناسازگار در درخواست‌های هم‌زمان را می‌گیرد. خواندن‌های بعدی فقط رکورد ذخیره‌شده را می‌خوانند. انتخاب یکی از هشت SVG در `/account` با API احراز‌شده ذخیره می‌شود؛ هدر همان لحظه تازه می‌شود و آواتار پنل مدیریت هم از همین داده استفاده می‌کند.

پیش‌نمایش بدون DB متفاوت است: انتخاب در فضای موقت همان بلیت نمایشی نگه داشته می‌شود؛ refresh آن را حفظ می‌کند ولی پایان نشست/راه‌اندازی مجدد سرور آن را دائمی نمی‌کند.

## استقرار

1. مثل قبل `DATABASE_URL`، کلید JWT و تنظیمات ورود واقعی را نگه دارید؛ `HADIRAN_TEST_MODE` در production خاموش باشد.
2. migration جدید `0015_account_avatars.sql` را با `npm run db:migrate` اجرا کنید؛ سپس build و استقرار عادی. migration قبلی تغییر نکرده و این migration جدول مستقل می‌سازد. راه‌اندازی پروژه نیز مسیر migration موجود را اجرا می‌کند؛ guard زمان اجرا برای ایجاد idempotent همین جدول وجود دارد.
3. از DB پشتیبان بگیرید و ابتدا روی staging اجرا کنید. برای ذخیرهٔ SVG انتخابی به دیسک کاربر نیازی نیست: SVGها دارایی عمومی نسخه‌بندی‌شده‌اند و فقط شمارهٔ انتخاب در DB می‌ماند.
4. در این نسخه آپلود عکس شخصی فعال نیست. فیلد `image_key` و خوانندهٔ خصوصی دیسک برای توسعهٔ بعدی آماده‌اند. `HADIRAN_MEDIA_ROOT` باید **مسیر مطلق واقعیِ mount پایدار خودتان** باشد؛ این کار مسیر mount را حدس نمی‌زند. ساختار آینده `<HADIRAN_MEDIA_ROOT>/avatars/<opaque-key>.<extension>` است، خارج از `public`، پوشهٔ build و ریپو.
5. خواننده فقط PNG/JPEG/WebP/AVIF با کلید محدود، مسیر realpath داخل پوشه و فایل حداکثر ۵MiB را می‌خواند. endpoint تصویر، احراز هویت، `private, no-store` و `nosniff` دارد و فقط تصویر همان حساب را می‌دهد. بدون فایل، ۴۰۴ و fallback SVG داریم. هیچ endpoint آپلود یا نوشتن روی mount فعلاً وجود ندارد.
6. برای فعال‌سازی واقعی آپلود بعدی، هنوز لازم است اعتبارسنجی محتوای باینری/ابعاد، حذف EXIF و بازکدگذاری امن، محدودیت نرخ/سهمیه، نوشتن اتمیک، پاک‌سازی فایل‌های قدیمی و پشتیبان‌گیری هماهنگ DB+disk اضافه شوند. SVG ارسالی کاربر پذیرفته نشود. نام فایل یا مسیر ورودی کاربر نباید مستقیم ذخیره شود. دیسک محلی یک replica بین چند replica مشترک نیست؛ برای چند نمونه، storage مشترک یا routing سازگار لازم است.

## شواهد آزمون نسخهٔ نهایی

- build بهینه، lint، TypeScript و whitespace check موفق.
- `qa/navigation_browser.py`: ۱۰ گروه رفتار و ۵۹ حالت چیدمان؛ صفر جابه‌جایی main هنگام بازشدن، حرکت خروج WAAPI، انتخاب/بیرون/Escape، Tab، rapid toggle، reduced motion، عرض‌های ۳۲۰ تا ۱۹۲۰، ارتفاع کم، آواتار و خروج.
- `qa/profile_live_browser.py`: ۱۳۴ حالت؛ ۱۲ مسیر عمومی در پنج عرض و دو تم، همهٔ آن مسیرها در ۳۲۰ CSS px با متن ۲۰۰٪، ورود واقعی عضو با کوکی Secure از طریق مبدأ HTTPS شبیه‌سازی‌شده، پنهان‌بودن لینک مالک و ماندگاری انتخاب آواتار.
- `qa/avatar_api.py`: احراز هویت، مقدار پیش‌فرض، validation صحیح بازهٔ ۰ تا ۷، جداسازی حساب‌ها و ماندگاری با نشست JWT جدید روی PostgreSQL محلی واقعی.
- رگرسیون قبلی نیز روی همین build دوباره اجرا شد: ۱۲ گروه API، ۹۶ حالت پنل/زبان/عرض، ورود و خرید/تحلیلگر واقعی در DB محلی، iframe بدون کوکی شبیه‌سازی‌شده و ۱۴ بررسی حفظ پرتره/فونت/سرویس‌ها/مهاجرت‌ها/وابستگی‌ها.
- در جریان‌های موفقِ ثبت‌شدهٔ فوق خطای runtime مرورگر و HTTP 5xx مشاهده نشد. این شواهد ادعای تأیید کامل WCAG یا آزمون همهٔ مسیرهای داده‌محور نیست.
- تست‌ها production، پیامک واقعی، انتقال پول، mount واقعی کاربر یا مبدأ خارجی Arena را لمس نکرده‌اند. پنج صفحهٔ قدیمی دربارهٔ من/دانشنامه/آزمایشگاه/دوره‌ها/تماس برای داده‌ها DB می‌خواهند؛ آزمون ریسپانسیو کامل آن‌ها روی DB محلی انجام شد، نه preview بدون DB. این نسخه آن صفحات را به دادهٔ ساختگی تبدیل نمی‌کند.
