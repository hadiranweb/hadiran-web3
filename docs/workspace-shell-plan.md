# پلن پوستهٔ میز کار — الهام ساختاری، نه پورت FounderOS

وضعیت: **قفل؛ برش ۱–۴ ساخته شد.**  
تاریخ: ۲۰۲۶-۰۹-۲۵  
زمینه: `/workspace` روی پرود زنده است (`689a4ed`)؛ OTP ست شده.  
الهام: [FounderOS-DEMO](https://github.com/Bennettxai/FounderOS-DEMO) فقط برای **پالس + کارِ باز + لینک جزئیات**.  
منبع جهان‌ها: `docs/ia-seo-map.md`. منبع دانش: `docs/knowledge-canonical-plan.md`.

```text
FounderOS ≠ هادیران
خانهٔ گفتگو ≠ کنسول اپراتور
پوسته ≠ سیستم‌عامل کسب‌وکار
عدد واقعی ≠ seed نمایشی
```

---

## ۰. هدف

Owner بعد از ورود، یک صفحهٔ میز ببیند که بگوید **الان چه خبر است** و **چه کاری باز است**، بعد با یک کلیک به جزئیات همان کار برود.

امروز `/workspace` فقط فهرست ثبت‌هاست. پوسته آن را به سه نوار تبدیل می‌کند، بدون افزودن ایجنت، مالی، ترید، اینباکس، یا مسیرهای `/brain` `/agents`.

---

## ۱. قفل‌ها (دست نزن)

| قفل | مقدار |
|---|---|
| محصول | هادیران؛ برند/مسیر/نام FounderOS وارد UI و URL نمی‌شود |
| خانه | `/` گفتگو می‌ماند؛ داشبورد روی `/` نمی‌آید |
| میز | فقط `/workspace*`؛ noindex؛ فقط `owner`؛ بیرون ناو اصلی |
| SoT | Postgres + Drizzle؛ مارکداون قالب ثبت |
| کپی | هیچ فایل FounderOS کپی نمی‌شود؛ بازنویسی بومی RTL |
| ظاهر | زبان بصری فعلی هادیران (slate/indigo، فارسی)؛ پوسته‌ی سیاه Monolith نه |
| CI | `ci.yml`، آلمان، `--no-cache` همیشگی دست نخورند |
| seed | `seed.ts` پرود/wipe ممنوع؛ عدد جعلی در پالس ممنوع |
| بیرون | LiveKit، درایو، زرین‌پال، Slack/Stripe/Notion، runtime ایجنت |
| سازمانی | Tenant/Org/pack در v1 نه |
| دانش | چرخهٔ Capture→…→Projection عوض نمی‌شود |

جدول‌های جهان حذف نمی‌شوند. لایهٔ canonical دانش بازنویسی نمی‌شود.

## ۲. از FounderOS چه چیزی الهام است / چه چیزی ممنوع

الهام **ساختار صفحه** (نه کامپوننت، نه pallete، نه سایدبار ۲۰ آیتمی):

| الگوی FounderOS | معادل هادیران |
|---|---|
| ردیف پالس با کاشیِ لینک‌دار (label / عدد / پانویس) | ۴ کاشی از SQL خودمان |
| فهرست «کار باز» | ثبت‌هایی که هنوز نمود عمومی ندارند |
| لینک جزئیات روی کاشی و ردیف | `/workspace/records/[id]` یا `/knowledge/[slug]` |
| fail-soft: نبود داده = خالی، نه ۵۰۰ | همان الگوی try/catch میز فعلی |
| وضعیت صادق: connected/error/not_configured | اگر جدولی نبود، کاشی «نامشخص» نه عدد دروغ |

عمداً نمی‌آید:

- `lib/nav.ts` و گروه‌های Operate / Agents / Intelligence
- Command Palette، Spotlight، Themes، CountUp تزئینی اجباری
- `/comms` `/funnel` `/finances` `/trading` `/agents` `/brain` `/doctor`
- SQLite، `lib/seed.ts`، کانکتور، G-Brain به‌عنوان SoT فایل
- کپی `PageHeader.tsx` / `Sidebar.tsx` / `StatTile`

اگر قطعهٔ substantive از MIT برداشته شود باید copyright بماند. این پلن **بازنویسی** است؛ notice لازم نیست.

## ۳. IA میز (یک نیت در URL)

ناو عمومی سایت عوض نمی‌شود. داخل میز، زیرناو کوتاه **فقط owner**:

```text
/workspace                 نمای پالس + کار باز + اخیراً منتشر
/workspace/capture         ثبت جدید (موجود)
/workspace/records/[id]    جزئیات ثبت + ارتقا (موجود)
```

مسیر جدید در این پلن ساخته نمی‌شود مگر اینکه برش بعدی صریحاً بخواهد.  
`/dashboard` و `/brain` و `/ops` ساخته نمی‌شوند.

لینک «میز کار» در `SessionMenu` همان `/workspace` می‌ماند.

---

## ۴. پالس — فقط عدد واقعی

کاشی‌ها روی `/workspace`، هر کدام لینک دارند. منبع: همان جداول canonical + جهان‌ها. اگر migrate نرسیده باشد، کاشی خالی/خطا نه صفر دروغینِ پنهان‌کننده.

| کاشی | معنی | منبع | لینک |
|---|---|---|---|
| ثبت خام | `semantic_records.status = captured` مال همین owner | `semantic_records` | `/workspace` لنگر `#open` |
| آمادهٔ ارتقا | ثبت‌هایی که captured نیستند ولی `promoted_memory_id` خالی است | `semantic_records` | همان لنگر |
| منتشر عمومی | `memory_items` با `approved` + `public` | `memory_items` | `/knowledge` |
| دانشنامه | ردیف `knowledge` با `memory_item_id` | `knowledge` ⋈ memory | `/knowledge` |

عمداً در برش اول نیستند: شمارش آزمایشگاه/دوره/موضوع (جهان‌های خالی را با صفر تزئینی شلوغ نکن). آن‌ها برش اختیاری بعدی‌اند و فقط لینک به صفحات عمومی موجود می‌دهند، نه ویرایشگر جدید.

پانویس هر کاشی یک جملهٔ فارسی کوتاه از همان query است (مثلاً «۳ ثبت منتظر ارتقا») نه اسپارک‌لاین ساختگی.

---

## ۵. کارِ باز و جزئیات

دو فهرست زیر پالس، نه کانبان ایجنت.

**کار باز** — ردیف‌هایی که owner باید به آن‌ها برگردد:

- `status = captured` یا `pending_review`
- یا هنوز `promoted_memory_id` ندارد

هر ردیف: عنوان، وضعیت، تاریخ به‌روزرسانی، لینک `/workspace/records/[id]`.

**اخیراً منتشر** — حداکثر ۱۰ حافظهٔ عمومی که این owner منبع‌شان بوده (`semantic_records.owner_id` + `promoted_memory_id`):

- عنوان، اسلاگ دانش اگر باشد
- لینک `/knowledge/[slug]` (نمود) و لینک دوم به ثبت مبدأ

خالی بودن هر دو فهرست متن صادق است: «کاری باز نیست» / «هنوز چیزی منتشر نشده.»

دکمهٔ موجود «ثبت جدید» در هدر میز می‌ماند.

## ۶. پوستهٔ بصری (هادیران، نه OS سیاه)

- `workspace/layout.tsx`: هدر میز (عنوان «میز کار»، لینک ثبت جدید، لینک خروج به خانه) + `children`
- عرض مثل الان حدود `max-w-3xl`؛ سایدبار تمام‌قد نمی‌آید
- کاشی‌ها: border slate، عدد بزرگ، برچسب کوچک — الگوی StatTile را با کلاس‌های فعلی بازنویسی می‌کنیم
- RTL و فارسی اجباری است؛ eyebrow انگلیسی و uppercase tracking FounderOS نه

گارد `requirePageOwner` روی layout یا هر صفحه؛ layout فقط chrome است نه جایگزینی گارد صفحات تودرتو (هر صفحه گارد خودش را نگه می‌دارد).

## ۷. برش‌ها (بعد از دستور ساخت، به ترتیب)

### برش ۰ — همین پلن

موثر: تصمیم. کد نه.

### برش ۱ — chrome میز

- `src/app/workspace/layout.tsx`: هدر مشترک + robots
- لینک‌های داخلی: نمای کلی / ثبت جدید
- صفحات capture و record از هدر مشترک استفاده می‌کنند؛ دکمهٔ تکراری حذف یا هم‌تراز می‌شود

### برش ۲ — پالس

- `src/lib/workspace/pulse.ts`: چهار count با try/catch
- ردیف کاشی در `workspace/page.tsx`
- بدون جدول جدید، بدون مهاجرت

### برش ۳ — کار باز + اخیراً منتشر

- همان صفحه؛ queryهای فهرست
- لینک جزئیات طبق §۵
- فهرست کامل ثبت‌ها (الان کل صفحه است) به بخش سوم «همهٔ ثبت‌ها» پایین صفحه می‌رود تا چیزی گم نشود

### برش ۴ — خالی و خطا

- empty state با CTA ثبت جدید
- اگر `0005` نباشد، پیام «لایهٔ دانش در این محیط آماده نیست» نه crash
- typecheck؛ `ci.yml` نه

### عمداً عقب (پلن جدا، دستور جدا)

- کاشی جهان‌ها (آزمایشگاه / دوره / موضوع) به‌صورت شمارش + لینک عمومی
- ویرایش شخص/پروژه/درس از میز
- گراف یال‌ها
- OG تصویر
- پوسته‌ی تیره، پالت فرمان، انیمیشن spotlight

## ۸. پذیرش برش ۱–۴

Owner وارد `/workspace` می‌شود و می‌بیند:

1. چهار کاشی با عدد واقعی (صفر صادق مجاز است)
2. فهرست کار باز با لینک به ثبت
3. فهرست اخیراً منتشر با لینک به `/knowledge/[slug]` وقتی چیزی ارتقا شده
4. ثبت جدید و ارتقا مثل امروز کار می‌کنند
5. مهمان/member به خانه یا ورود می‌روند؛ ناو عمومی بدون «میز کار»
6. `/` و FounderOS-مانند مسیر جدید نیست
7. دیپلوی docs-only نیست؛ این برش UI است و CD را می‌زند — مثل لایهٔ دانش. `ci.yml` دست نخورده
