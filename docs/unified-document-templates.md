## نتیجهٔ پیاده‌سازی

چهار انتخاب نمایشی در کاتالوگ مشترک قرار دارد:

| شناسه | طرح | سازگاری |
|---|---|---|
| `hadiran` | هادیران | ارزیابی عمومی |
| `casio-ss` | کاسیو ماتریسی | هر بستهٔ عمومی دارای یافتهٔ لایه‌ای |
| `casio-research` | کاسیو پژوهش | هر بستهٔ عمومی دارای یافتهٔ لایه‌ای |
| `system-diagnosis` | عارضه‌یابی سیستم کسب‌وکار | بستهٔ عارضه‌یابی سیستم |

این‌ها قالب سندند، نه آزمون‌های جداگانه. بسته، جدول پاسخ، API، seed یا موتور امتیازدهی قدیمی کاسیو برنگشته است. سند‌ساز و ویرایشگرهای مشترک موجودِ main استفاده می‌شوند؛ UI و قرارداد دسترسی/تحویل موجود جایگزین نشده‌اند.

- `document-templates.ts`: کاتالوگ و تشخیص سازگاری؛ شناسه‌های دو طرح کاسیو مستقل‌اند.
- `document-template-defaults.ts`: پیش‌فرض‌های نمایشی بدون اتصال DB؛ خروجی‌های قبلی store نیز بازصادر می‌شوند.
- `document-casio-defaults.ts`: انتقال انتخابی HTML/CSS از مرجع تاریخی `7c3703a`؛ طرح پژوهش به Mustache قابل ویرایش تبدیل شده است.
- `document-templates-store.ts`: ادغام پیش‌فرض مجازی با قالب پایه و تنظیم نویسنده؛ تنظیم موجود اولویت دارد.
- `persist-report.ts`: حفظ قرارداد `chromeSnapshot`؛ هنگام ذخیره/تبدیل صریح، ایجاد ردیف متادیتای قالبِ شناخته‌شده با `ON CONFLICT DO NOTHING` پیش از ارجاع گزارش.
- `document-chrome.ts`: رندر مشترک، سقف نمره از داده و صفحه‌های ادامهٔ جدول پژوهش در گروه‌های حداکثر پنج لایه؛ بدون تکرار نمودار و زمینه در صفحهٔ ادامه.
- سه SVG تاریخی در مسیر بی‌طرف `public/document-templates/casio/` و فونت IRANSharp موجود استفاده می‌شوند.

نمایش فهرست پیش‌فرض‌ها ردیف قالب جدید نمی‌سازد. با این حال schema guard قدیمیِ main هنوز در مسیر store حضور دارد؛ ادعای بدون‌اثر‌بودن کل درخواست دیتابیسی مطرح نیست.

### تکرار بررسی‌ها بدون راه‌اندازی برنامه

از ریشهٔ checkout و بدون URL دیتابیس واقعی؛ خروجی‌ها در همان شاخه و بیرون از محصول می‌مانند:

```bash
mkdir -p qa-artifacts
QA_OUT="$PWD/qa-artifacts"
DATABASE_URL= node --loader ./qa/typescript-loader.mjs --test qa/document-template-unification.test.mjs
DATABASE_URL= npm run typecheck
DATABASE_URL= ./node_modules/.bin/eslint src/lib/analyzers/document-templates.ts src/lib/analyzers/document-templates-store.ts src/lib/analyzers/document-template-defaults.ts src/lib/analyzers/document-casio-defaults.ts src/lib/analyzers/document-chrome.ts src/lib/analyzers/persist-report.ts
DATABASE_URL= npm run build
DATABASE_URL= node --loader ./qa/typescript-loader.mjs qa/build-document-preview.mjs "$QA_OUT/unified-document-templates-preview.html"
DATABASE_URL= node --loader ./qa/typescript-loader.mjs qa/build-document-print-fixtures.mjs "$QA_OUT/print-boundary-fixtures.json"
python qa/browser-document-templates.py --preview "$QA_OUT/unified-document-templates-preview.html" --output "$QA_OUT" --boundaries "$QA_OUT/print-boundary-fixtures.json"
```

پیش‌نمایش و فایل متادیتای ساختگی آن کنار هم ساخته می‌شوند؛ اسکریپت مسیر `/home/user/research/` را hard-code نمی‌کند. آزمون مرورگر به Python Playwright، Chromium و کتابخانه‌های سیستم آن نیاز دارد؛ هیچ وابستگی npm اضافه نشده است. `next build` ممکن است فایل تولیدی `next-env.d.ts` را به‌روز کند؛ این تغییر جزو وصله نیست.

## باقی‌مانده‌ها و خط قرمزها

1. زنجیرهٔ احراز هویت‌شدهٔ «ارزیابی عمومی → گزارش → انتخاب قالب → ساخت/ویرایش → ذخیره/بازخوانی → چاپ/دانلود» هنوز با دیتابیس آزمایشیِ واقعی تأیید نشده است. آزمون ذخیره/هم‌زمانی/FK در PostgreSQL واقعی و نقش‌های مالک/نویسنده/خریدار باقی است.
2. برای اتصال بعدی، ابتدا طرح و ledger واقعی، پشتیبان تأییدشده و حساب آزمایشی بررسی شوند. اجرای runner موجود یا start با URL واقعی نباید ابزار تشخیص باشد؛ migration تاریخی `0037` مسیر مخرب دارد و اجرا نشده است.
3. migration جدیدی برای این وصله اضافه نشده و migrationهای تاریخی تغییر نکرده‌اند. حذف‌های تاریخی `0036` با بازگرداندن پیش‌فرض‌های کد جبران نمی‌شود؛ قالب/گزارش سفارشی حذف‌شده به بازیابی از پشتیبان نیاز دارد.
4. چاپ متن‌های بسیار بلند، زمینه‌های متعدد، طرح افقی/حاشیهٔ سفارشی و قالب HTML/CSS دست‌کاری‌شده باید جداگانه بررسی شود. تعداد صفحات پژوهش مربوط به برگ‌های برنامه‌ریزی‌شده است؛ overflow ناشی از متن بلند می‌تواند صفحهٔ فیزیکی بیشتری بسازد.
5. قواعد پرداخت و دسترسی main عمداً در این مرحله تغییر نکرده‌اند. تعارض احتمالی دروازهٔ اجرای پولی موجود با قاعدهٔ پیشین «ارزیابی و خلاصه رایگان» موضوع تصمیم جداگانه است.
6. این تحویل تأیید آماده‌بودن تولید نیست؛ مجوز تازه‌ای برای push، تغییر main، دیتابیس یا استقرار ایجاد نمی‌کند.

## شواهد در این checkout یکپارچه‌سازی

- پیش‌نمایش مستقل و متادیتای ساختگی آن در `qa-artifacts/` کنار هم ساخته می‌شوند؛ نام‌ها و نمره‌ها واقعی نیستند. فایل HTML را برای دیدن/چاپ دانلود و در مرورگر باز کنید.
- بررسی‌های واقعاً اجراشده در این شاخه: ۱۴/۱۴ آزمون Node، typecheck، ESLint شش فایل محصول و `next build` موفق؛ `DATABASE_URL` خالی بود. Build چند هشدار موجود مخزن دربارهٔ Middleware/Edge و دسترسی پویای filesystem داد؛ شکست build نبود. تغییر تولیدی `next-env.d.ts` به نسخهٔ مبنا برگشت.
- آزمون مرورگر Chromium و PDF/۲۰ مرز چاپ در این محیط اجرا نشدند: Python Playwright و Chromium موجود نبودند و وابستگی تازه نصب نشد. نتایج چهارتایی/۲۰حالتهٔ بالا فقط نتایج محیط مبدأ هستند و جای QA این محیط را نمی‌گیرند.
- این شواهد اثبات ذخیره‌سازی PostgreSQL، دسترسی واقعی، تحویل فایل یا چاپ هر متن دلخواه نیستند.
