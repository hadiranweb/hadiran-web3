# override صفحه خانه

وضعیت: asset pipeline جدید اعمال شده؛ بررسی بصری external `<use>` در مرورگر هنوز باقی است
مسیر: `/`

## نیت صفحه

کاربر باید بدون عبور از لندینگ یا انتخاب دسته‌بندی بتواند مسئله خود را بنویسد و پاسخ را به دانش، پروژه، دوره یا موضوع مرتبط وصل کند.

## سلسله‌مراتب

1. ناوبری سبک و قابل فهم.
2. جمله هویتی کوتاه که توضیح دهد هادیران چه مسئله‌ای را حل می‌کند.
3. پرتره به‌عنوان عنصر هویت و دعوت به تعامل، نه تصویر تزئینی مستقل.
4. گفتگو و ورودی به‌عنوان اقدام اصلی و مرکز صفحه.
5. ارجاع‌های پاسخ به جهان‌های اکوسیستم.

## overrideهای خانه

- الگوی Hero-Centric از design-system عمومی روی این صفحه اعمال نمی‌شود.
- chat باید در اولین viewport یا بلافاصله پس از مقدمه قابل دسترس باشد.
- `HomeChat` نباید برای آماده شدن پرتره قفل یا غیرفعال شود.
- دکمه ارسال و ورودی در موبایل باید ارتفاع لمسی حداقل 44px داشته باشند و بین کنترل‌های مجاور حداقل 8px فاصله باشد.
- حالت انتظار باید فضای پیام را جابه‌جا نکند؛ پیام وضعیت پایدار و `aria-busy` ارائه شود.
- پاسخ‌های طولانی در عرض خوانا بمانند؛ پنل پیام می‌تواند عریض‌تر باشد، اما متن هر پیام بیش از حدود 75ch نشود.
- رنگ اصلی اقدام `#4F46E5` است؛ cyan فقط برای نشانه تعامل و داده به‌کار رود.
- پرتره در assemble اولیه path-per-piece باقی بماند؛ هیچ tile، grid یا raster interaction اضافه نشود.
- هنگام `prefers-reduced-motion` تصویر ثابت نمایش داده شود؛ replay متحرک غیرفعال باشد.

## فهرست تغییرات مرحله‌ای پیشنهادی

### مرحله 0: صحت و پایداری

وضعیت: اجرا شده، با یک بررسی دستی کامل که هنوز باید در مرورگر انجام شود.

- حذف fallback transition/animation از مسیر پرتره و نگه‌داشتن fallback ثابت.
- اصلاح ترتیب ثبت session flag تا Strict Mode باعث ثبت زودهنگام نشود.
- `typecheck` و `lint` موفق هستند.
- پاسخ HTTP صفحه خانه در preview موفق است.
- بررسی دستی کامل replay، session و reduced motion هنوز باقی است.

### pipeline asset پرتره

وضعیت: اعمال شده و build موفق است.

- source جدید در `assets/portrait/hadiran-portrait.source.svg` قرار گرفت.
- asset نهایی با 1603 path و id مستقل در `public/hadiran-portrait.svg` تولید شد.
- `pieces.generated.ts`، `tiles.generated.ts` و pipeline grid حذف شدند.
- metadata کلاینت به viewBox و تعداد pathها محدود شد.
- component به‌جای کپی `d` از external `<use>` روی همان SVG استفاده می‌کند.
- تست دستی render شدن `<use>` در مرورگر و اندازه‌گیری FPS هنوز باقی است.

### مرحله 1: بنیاد visual و accessibility

وضعیت: برای پوسته اصلی و صفحه خانه اجرا شده است.

- توکن‌های رنگ و سطح در `globals.css` اضافه و برای body، nav، footer، chat، action و portrait halo استفاده شدند.
- focus-visible عمومی با حلقه قابل مشاهده و `scroll-padding` اضافه شد.
- ورودی خانه label واقعی، شناسه پایدار و وضعیت قابل دسترس دارد.
- پنل گفتگو با `role="log"`، `aria-live` و `aria-busy` علامت‌گذاری شد.
- کنترل‌های اصلی ناوبری و ارسال در موبایل حداقل 44px هستند.
- loading spinner حذف و با پیام متنی پایدار جایگزین شد.
- لینک‌های جهان‌های خانه و ارجاع‌های chat از tokenهای semantic استفاده می‌کنند.
- صفحات داخلی هنوز به‌صورت کامل از tokenهای جدید مهاجرت نکرده‌اند.

### مرحله 2: سلسله‌مراتب خانه

- نزدیک کردن chat به اولین viewport بدون تبدیل صفحه به لندینگ تبلیغاتی.
- کاهش رقابت بصری بین nav، portrait و chat.
- مشخص کردن وضعیت‌های خالی، انتظار، خطا و پاسخ همراه با ارجاع.

### مرحله 3: performance و polish

- اندازه‌گیری هزینه 1603 path در موبایل و دسکتاپ.
- نگه‌داشتن transform و opacity برای حرکت و جلوگیری از layout shift.
- آزمون replay، session، reduced motion و resize در چهار عرض هدف.

## معیار اندازه‌گیری صفحه

- زمان تا قابل‌استفاده بودن input نباید به animation پرتره وابسته باشد.
- هیچ جابه‌جایی ناگهانی در محل input هنگام ورود یا دریافت پاسخ رخ ندهد.
- تمام مسیرهای اصلی با keyboard قابل استفاده باشند.
- در reduced motion هیچ scatter یا replay خودکار دیده نشود.
- در 375px متن، دکمه ارسال و پنل پیام بدون بریدگی یا scroll افقی دیده شوند.
